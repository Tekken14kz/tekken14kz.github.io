# Подлесок

Личный цифровой сад: связанные заметки, которые растут и переписываются, вместо ленты постов.
Статический сайт без зависимостей — только Node и папка markdown-файлов.

## Как это устроено

```
notes/        одна заметка = один .md файл, единственный источник правды
src/          style.css, app.js, shell.html — внешний вид и поведение
build.mjs     генератор: читает notes/, считает связи, собирает dist/
dist/         результат сборки, его и выкладываем (в git не хранится)
artifact/     та же страница одним файлом — для публикации артефактом
```

Сборка занимает доли секунды и не требует `npm install`: в генераторе нет ни одной внешней
зависимости.

## Как добавить заметку

Создать файл `notes/имя-латиницей.md`:

```markdown
---
title: Как называть заметки
stage: seed
planted: 2026-08-30
tended: 2026-08-30
---

Текст заметки. Ссылка на соседнюю: [[obratnye]] или с другой подписью:
[[obratnye|обратные ссылки]].
```

Поля обязательные все четыре. `stage` — одно из трёх:

| значение | смысл | как выглядит |
|---|---|---|
| `seed` | росток, мысль на два абзаца | пустой кружок |
| `grow` | растёт, выводы ещё меняются | наполовину залитый |
| `ever` | вечнозелёная, ей можно пользоваться | залитый целиком |

`planted` — дата посадки, `tended` — дата последней правки. В саду вторая важнее первой,
по ней же сортируется указатель.

Имя файла — это адрес заметки: `notes/obratnye.md` → `#/obratnye`.

### Что понимает markdown

Абзацы, списки `- `, цитаты `> `, подзаголовки `## `, `**жирный**`, `*курсив*`,
`` `код` ``, обычные ссылки `[текст](https://...)` и вики-ссылки `[[имя]]`.
Этого достаточно для заметок; если чего-то не хватает — дописывается в `markdown()`
внутри `build.mjs`, там полсотни строк.

Обратные ссылки и карта считаются сами из графа `[[...]]` — руками ничего проставлять не нужно.
Сборка предупредит о ссылках в никуда и о заметках, не связанных ни с чем.

## Локально

```bash
node build.mjs --serve
```

Откроется на `http://localhost:4321`. Правишь заметку — перезапускаешь команду.

Просто собрать, без сервера:

```bash
node build.mjs
```

## Настройки

Всё в начале `build.mjs`, объект `SITE`: название, подпись, описание для поисковиков,
и `entry` — какие заметки открыты при заходе на главную.

## Выложить в интернет

### GitHub Pages

Репозиторий уже содержит `.github/workflows/deploy.yml` — сборка и публикация по пушу в `main`.

1. Создать пустой репозиторий на GitHub (без README и .gitignore).
2. Привязать и запушить:
   ```bash
   git remote add origin git@github.com:ИМЯ/podlesok.git
   git push -u origin main
   ```
3. В настройках репозитория: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Через минуту сайт будет на `https://ИМЯ.github.io/podlesok/`.

### Cloudflare Pages

Быстрее и без Actions. На `dash.cloudflare.com` → **Workers & Pages → Create → Pages →
Connect to Git**, выбрать репозиторий и указать:

- Build command: `node build.mjs`
- Build output directory: `dist`

Дальше каждый пуш пересобирает сайт сам.

### Свой домен

- GitHub Pages: положить файл `CNAME` с доменом в `dist/` (проще всего дописать одну строку
  в конец `build.mjs`) и прописать у регистратора A-записи GitHub.
- Cloudflare Pages: вкладка **Custom domains**, всё остальное сделается само.
