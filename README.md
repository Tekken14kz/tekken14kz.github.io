# Подлесок

Личный цифровой сад: связанные заметки, которые растут и переписываются, вместо ленты постов.
Статический сайт без зависимостей — только Node и папка markdown-файлов.

Живёт на https://tekken14kz.github.io

## Как это устроено

```
notes/        одна заметка = один .md файл, единственный источник правды
src/          style.css, app.js, shell.html — внешний вид и поведение
build.mjs     генератор: читает notes/, считает связи, собирает dist/
dist/         результат сборки, его и выкладываем (в git не хранится)
artifact/     та же страница одним файлом — для публикации артефактом
```

Сборка занимает доли секунды и не требует `npm install`: в генераторе нет ни одной внешней
зависимости.

Что оказывается в `dist/`:

- `index.html` — главная
- `имя-заметки/index.html` — **своя страница на каждую заметку**, с готовым HTML,
  своим `<title>`, описанием и canonical
- `feed.xml` — лента Atom по дате последнего ухода
- `sitemap.xml`, `robots.txt` — чтобы поисковик нашёл все заметки
- `404.html` — на случай переименованной заметки
- `style.css`, `app.js`

## Как добавить заметку

Создать файл `notes/имя-латиницей.md`:

```markdown
---
title: Как называть заметки
stage: seed
planted: 2026-08-30
tended: 2026-08-30
---

Текст заметки. Ссылка на соседнюю — по имени файла или по заголовку:
[[obratnye]], [[Обратные ссылки]], [[obratnye|с другой подписью]].
```

Поля обязательные все четыре. `stage` — одно из трёх:

| значение | смысл | как выглядит |
|---|---|---|
| `seed` | росток, мысль на два абзаца | пунктирный штрих |
| `grow` | растёт, выводы ещё меняются | прерывистый штрих |
| `ever` | вечнозелёная, ей можно пользоваться | сплошная линия |

Стадия показана сплошностью линии, а не иконкой: чем больше краски, тем заметка взрослее.
Тот же приём работает на подчёркивании ссылки в тексте (видно, что откроется, ещё до клика)
и на узлах карты.

`planted` — дата посадки, `tended` — дата последней правки. В саду вторая важнее первой,
по ней сортируется указатель и строится лента.

Имя файла — это адрес заметки: `notes/obratnye.md` → `/obratnye/`.

### Ссылки как в Obsidian

`[[имя-файла]]` и `[[Заголовок Заметки]]` работают одинаково — регистр и пробелы неважны.
Значит, папку `notes/` можно открыть как обычный волт Obsidian и писать прямо там,
с автодополнением ссылок и родным графом.

Чтобы показать двойные скобки в тексте, не превращая их в ссылку, оберни их в обратные
кавычки: `` `[[имя]]` ``.

### Что понимает markdown

Абзацы, списки `- `, цитаты `> `, подзаголовки `## `, `**жирный**`, `*курсив*`,
`` `код` ``, обычные ссылки `[текст](https://...)` и вики-ссылки. Этого достаточно для
заметок; если чего-то не хватает — дописывается в `markdown()` внутри `build.mjs`.

Обратные ссылки, карта и **контекст** (предложение, в котором стоит ссылка) считаются сами
из графа — руками ничего проставлять не нужно. Сборка предупредит о ссылках в никуда
и о заметках, не связанных ни с чем.

## Горячие клавиши

| клавиша | что делает |
|---|---|
| `/` | поиск |
| `↓` `↑` | по списку заметок |
| `Enter` | открыть |
| `m` | карта сада |
| `Esc` | закрыть карту, очистить поиск |

Кнопка **Тема** перебирает три состояния: как в системе → светлая → тёмная. Выбор
запоминается в браузере и применяется до первой отрисовки, без мигания.

## Локально

```bash
node build.mjs --serve
```

Откроется на `http://localhost:4321`. Правишь заметку — перезапускаешь команду.

Просто собрать, без сервера:

```bash
node build.mjs
```

## Настройки

Всё в начале `build.mjs`, объект `SITE`:

| поле | смысл |
|---|---|
| `title`, `tagline` | название и подпись в углу |
| `description` | описание для поисковиков и ленты |
| `url` | адрес сайта, нужен для canonical, sitemap и ленты |
| `base` | подпапка, если сайт не в корне домена (`/podlesok/`) |
| `entry` | какие заметки открыты при заходе на главную |

## Выложить в интернет

### GitHub Pages

В репозитории лежит `.github/workflows/deploy.yml` — сборка и публикация по пушу в `main`.

```bash
git add -A && git commit -m "новая заметка" && git push
```

Через минуту заметка на сайте.

Если поднимаешь с нуля: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Репозиторий с именем `логин.github.io` GitHub по умолчанию собирает старым Jekyll-режимом —
источник нужно переключить явно, иначе он выложит отрендеренный README вместо сайта.

### Cloudflare Pages

**Workers & Pages → Create → Pages → Connect to Git**, выбрать репозиторий и указать:

- Build command: `node build.mjs`
- Build output directory: `dist`

### Свой домен

- GitHub Pages: положить файл `CNAME` с доменом в `dist/` (дописать одну строку в конец
  `build.mjs`) и прописать у регистратора A-записи GitHub. Не забыть поменять `SITE.url`.
- Cloudflare Pages: вкладка **Custom domains**, всё остальное сделается само.
